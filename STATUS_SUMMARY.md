## 🚧 Known Issues

### Critical: Array Index Bug in Self-Hosted Compilation

**Status**: WORKAROUND IMPLEMENTED ✅

**Problem**: When the self-hosted TSN compiler compiles itself, it generates buggy LLVM IR for array access in loops:

```llvm
; WRONG CODE (generated by self-hosted compiler):
%length_ptr = getelementptr inbounds %Array, ptr %arr, i32 0, i32 3
%index = load i32, ptr %length_ptr  ; ← BUG: loads from length field, not loop var
%result = call ptr @Array_get_impl(ptr %array, i32 %index)
```

**Correct Code** (generated by TypeScript compiler):
```llvm
%index = load i32, ptr %i  ; ← Correct: loads from loop variable
%result = call ptr @Array_get_impl(ptr %array, i32 %index)
```

**Impact**:
- ~72 occurrences found in mir-builder-flat and mir-codegen-flat
- Causes crashes, infinite loops, incorrect results
- Only affects self-compiled code, NOT TS-compiled code

**Workaround**:
- Use TypeScript/Deno compiler for bootstrap (current approach)
- Python script `fix_array_get_v2.py` can detect and fix bugs post-compilation

**Root Cause**: Unknown - investigating MIR loop code generation

### Runtime Crashes

- ❌ Self-hosted compiler crashes when compiling complex programs (including itself)
- ❌ Crash occurs in `MIRFunction` constructor or `buildFunction`

## 🎯 Current Approach: Bootstrap Compiler

Due to self-hosting bugs, we use a **bootstrap approach**:

1. **TypeScript Compiler** (via Deno) compiles TSN → LLVM IR
2. **Clang** links LLVM IR → Native executable
3. **Result**: Working TSN compiler (`tsnc.exe`)

**Advantages**:
- ✅ Stable and reliable
- ✅ Generates correct LLVM IR
- ✅ Can compile real TSN programs

**Limitations**:
- ⚠️ Requires Deno/TypeScript for building
- ⚠️ Not 100% self-hosted (yet)
