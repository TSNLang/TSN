## Known Limitations

### 1. String Literal Newlines
Generated IR contains `\n` instead of actual newlines:
```llvm
; Generated by TSN Compiler v2\n\ndeclare void @print_i32(i32)\n
```

**Impact**: Low - manually fixable, doesn't affect execution
**Root cause**: TSN string handling doesn't process escape sequences
**Workaround**: Manually replace `\n` with actual newlines in output

### 2. Hardcoded Input/Output Paths
Current `main.tsn` hardcodes:
```tsn
let inputPath: string = "compiler/test-phase23.tsn";
let outputPath: string = "output.ll";
```

**Impact**: Medium - can't specify custom files
**Solution**: Need command-line argument parsing (future feature)

### 3. TSN Compiler Cannot Compile Itself Yet
While TSN compiler (compiled by Python) can compile simple code, it **cannot compile its own source** yet.

**Blockers identified**:
1. **Object field access limitations** - compiler uses `this.tokens`, `this.current` extensively
2. **Method calls** - needs `obj.method()` syntax fully working
3. **String methods** - uses `.length`, string comparison
4. **Array methods** - needs `.push()`, `.get()`, `.length` working reliably
5. **Constructor parameters** - bootstrap compiler doesn't assign them properly
6. **Import system** - currently imports are compiled but not linked
7. **Generic types** - `Array<Token>`, `Array<Expr>` need proper handling
