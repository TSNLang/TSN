### Grammar Support:

#### Before Phase 34.5:
```
ClassMember ::= 'constructor' '(' ... ')'
             |  'field' IDENTIFIER ':' TYPE ';'
             |  [ERROR on 'function' keyword]
             |  [ERROR on bare IDENTIFIER]
```

#### After Phase 34.5:
```
ClassMember ::= 'constructor' '(' ... ')'
             |  'function' IDENTIFIER '(' ... ')'     // ✅ NEW
             |  'field' IDENTIFIER ':' TYPE ';'       // ✅ IMPROVED
             |  IDENTIFIER ':' TYPE ';'               // ✅ NEW (inline)
             |  IDENTIFIER '(' ... ')'                // (fallback)
```

## 🎓 What We Learned

### 1. Bootstrap Independence
**Problem**: Fixed parser.tsn but still crashes.  
**Insight**: Bootstrap compiler (Python) has separate code path.  
**Lesson**: Both implementations must stay in sync.

### 2. Keyword Priority
**Problem**: Parser checks IDENTIFIER first, misses FUNCTION.  
**Insight**: Explicit keywords need early checks.  
**Lesson**: Check keywords before generic fallback.

### 3. Lookahead Strategy
**Problem**: Can't distinguish field from method without lookahead.  
**Insight**: Peek at next token type (COLON vs LPAREN).  
**Lesson**: 1-token lookahead sufficient for TSN grammar.

### 4. Incremental Validation
**Problem**: Complex failures hard to debug.  
**Insight**: Simple tests isolate issues.  
**Lesson**: test-field-inline → ast.tsn → lexer.tsn → parser.tsn
