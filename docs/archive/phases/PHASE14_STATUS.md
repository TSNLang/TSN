## ✅ Features Implemented

### 1. Multiple Functions
**Parser**:
- Loop through all tokens parsing function declarations
- Each function parsed independently

**Codegen**:
- `emitFunctions()` iterates through all functions
- Each function gets own `define` block
- Proper function separation with blank lines

### 2. Function Calls (No Arguments)
**Syntax**: `functionName()`

**Parser**:
```typescript
// In parseSimpleBlock, detect function call:
if (this.check("IDENTIFIER")) {
    let name = token.lexeme;
    if (this.check("LPAREN")) {
        // Function call!
        valueExpr.kind = "CallExpr";
        valueExpr.callee = name;
    }
}
```

**Codegen**:
```typescript
private emitCall(expr: Expr): string {
    let resultReg = this.newRegister();
    this.output.push("  " + resultReg + " = call i32 @" + expr.callee + "()");
    return resultReg;
}
```

### 3. File Output
- Read source from string or file
- Generate LLVM IR
- Write to .ll file using `writeText()`

**Known Issue**: String `\n` handled as literal - requires manual fixing for now

## 🔧 Technical Details

### Generated LLVM IR
```llvm
; Generated by TSN Compiler v2

declare void @print_i32(i32)
declare void @_T_log_P_ptr(ptr)

define i32 @getValue() {
entry:
  ret i32 5
}

define i32 @main() {
entry:
  %r0 = call i32 @getValue()
  ret i32 %r0
}
```

### Call Instruction Format
```llvm
%result = call <return_type> @<function_name>(<args>)
```

For no arguments: `%r0 = call i32 @getValue()`

## 🐛 Workarounds

### Detecting CallExpr
**Problem**: Can't check `kind` field

**Solution**: Check `callee` field
```typescript
if (expr.callee != "") {
    return this.emitCall(expr);
}
```

### String Newlines
**Problem**: Runtime writes `\n` as literal

**Solution**: Manually fix generated .ll files for now
- Future: Fix in runtime or use different string handling
